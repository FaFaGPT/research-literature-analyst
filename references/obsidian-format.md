# Obsidian 文件约定

## 文件布局

先检查已有目录、笔记命名和属性字段，沿用其约定。全新题目默认：

```text
research-notes/<主题短名>/
  00-研究地图.md
  01-Papers/
    <第一作者>-<年份>-<标题短名>.md
  02-Directions/
    2.1-<方向短名>.md
  03-Concepts/
    <理论、方法或数据短名>.md
  04-Claims/
    C001-<判断短名>.md
  05-Evidence/
    M001-<比较问题短名>.md
  90-补读与检索记录.md
```

这个目录可以作为独立 vault 打开，也可放入现有 vault。向已有 vault 写入前按实际 vault 根目录计算内部链接；不要把主题子目录误当作 vault 根。没有指定 vault 时只创建笔记目录，不改 `.obsidian` 设置。

主题页保留规定的主干及实质性摘要；方向页展开对应的两个子部分；论文页包含原文证据和深读；概念页只为有复用价值的理论、方法或数据建立。

`04-Claims/` 保存研究地图中的关键判断；`05-Evidence/` 保存需要独立引用或跨方向复用的证据矩阵。小矩阵也可直接放在方向页，避免重复。Claim 的元数据和状态见 [证据综合规则](evidence-synthesis.md)。

关联链为“topic → paper → claim → concept/direction → evidence matrix → 原文证据”。论文的 `claims`、Claim 的 `supporting_papers`/`challenging_papers` 及方向/矩阵的 `claims` 使用引用的内部链接列表；单纯关联不自动等于支持。

## 命名、标识与去重

- 笔记名不使用 Windows 禁用字符 `< > : " / \ | ? *`、控制字符、末尾空格或句点，也避开设备保留名；Obsidian 链接含义特殊的 `# ^ [ ]` 和 `%%` 也避免写入文件名。
- 采用简短可读文件名，完整题名放 `title` 和 `aliases`；同名时追加题名缩写或稳定标识。
- 每篇论文保留稳定 `id`，优先 DOI，其次预印本 ID，其次核实后的作者/年份/标题标识。新条目先查重复，正式版出现时更新原节点，避免拆成两个互不相干的节点。
- Claim 使用 `claim_id`，矩阵使用 `id`；各类型内保持唯一。Claim 状态变化不重建 ID，命题含义实质改变时新建并显式关联旧节点。论文版本更新保留原 ID，补 DOI/版本对应关系。
- 已有论文文件名通常保留；确需更名时同步修复入站链接，不能假设直接文件操作会触发 Obsidian 自动改链。

## 属性与 Markdown

- UTF-8 Markdown；每个文件一个一级标题，下面用二至六级标题。
- YAML 放在文件开头。`tags`、`aliases`、`authors`、`topics` 等使用列表，缺值用 `null` 或空列表；记录 `created`、`updated`、`type` 和必要来源。
- 日期使用 `YYYY-MM-DD`。同名属性维持一致的数据类型；年份为数字或 `null`。
- `reading_priority` 使用 Tier A/B/C/D；它不能替代 `reading_status`。旧库增量更新时为本次读到的论文补优先级与理由，不为未复核的旧笔记伪填。
- 含冒号、引号等字符的字符串正确引用或用 YAML 序列化器输出；内部链接在 YAML 中必须是引号包裹的字符串。
- `tags` 属性中的标签不带 `#`；正文使用标签时带 `#`。用少量学科、理论、方法标签，避免每个名词都标签化。
- 数学使用 `$...$` 或 `$$...$$`；公式与原文编号的对应关系写在附近。必要时使用简单 Mermaid 图；图只是帮助理解，不能代替机制解释。
- 使用原生 Markdown、属性和内部链接完成交付；Dataview、Templater、Zotero 等插件只在用户需要或已有约定时接入。

## 内部链接与可追溯来源

基本形式：`[[节点文件名]]`；自定义显示文字：`[[节点文件名|论文短题名]]`。有重名或跨目录歧义时使用相对于 vault 根的路径和 `/`，Windows 上也如此。

例如，独立 vault 中的论文可以链接：

```markdown
所属主题：[[00-研究地图]]
相关方向：[[02-Directions/2.1-方向短名]]
该方法使用 [[03-Concepts/方法短名]]，用于解决……
```

表格内尽量使用无别名的 `[[节点名]]`；需要别名时正确转义竖线，防止破坏表格。

每条知识关系尽量说明动词，例如“继承某理论的假设”“反驳某实验条件下的结论”。在论文或概念页写回所属主题/方向，便于往返导航；Obsidian 也会据链接生成反向链接。

所有内部链接应指向实际存在的文件或有效标题。确有后续价值但尚未创建的节点，用普通文字列入补读队列，创建后再改成链接；不要为凑图谱生成空洞概念页。这样待办不会被误当作已存在的知识节点。

外部来源用 `[论文原文](https://...)` 等稳定链接；内部链接不能替代外部证据。正文附近给来源定位，末尾保留来源清单。聊天专用引用标记不写入 `.md` 文件。

## 增量更新与交付

编辑前读取相关文件，保留用户批注、既有 `id`、`created` 和其他属性。更新实质变动处以及 `updated`；没有变化时不反复重写。新旧观点发生实质变化时，在“更新记录”简述证据和修订理由。

通常直接生成 `.md` 文件；工具不可写文件或用户只要聊天输出时，按相对文件路径分别给出完整 Markdown 内容，明确它们尚未保存。

交付前检查：YAML 解析、内部链接目标、标题锚点、重名冲突、表格格式、遗留模板变量、来源可追溯性。可以用当前可用的简单脚本辅助检查，无需为阅读任务安装 Obsidian 或其他插件。

可运行 [validate_vault.py](../scripts/validate_vault.py) 检查实际 vault 根目录。模板允许 `{{...}}`，生成笔记不得残留；新模板中的日期占位符已加引号，原始模板的 YAML 也应可解析。该检查只能验证结构，不验证论文真实性、Claim 支持关系或科学结论。

## 格式依据

采用 Obsidian 官方 [Internal links](https://help.obsidian.md/links) 和 [Properties](https://help.obsidian.md/properties) 所支持的内部链接与 YAML 属性格式。核对日期：2026-10-01。目录层级、命名和阅读状态是本 skill 的约定，可按已有 vault 调整。
